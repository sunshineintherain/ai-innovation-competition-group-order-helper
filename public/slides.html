The campus lunch decision

Fifteen minutes in common

Aster finishes class at 12:20, wants a RM12 lunch set and must collect by 12:50.

Birch wants a RM10 rice bowl and can collect from 12:35 to 13:00.

In a group chat, someone has to compare the windows, check which items count and ask everyone again when plans change.

Fictional scenario at the Atrium counter · Common window 12:35–12:50
Proposed solution

One request per student

“I want the RM12 lunch set from Demo Café. I can pick it up between 12:20 and 12:50 today.”

The assistant finds the catalog item and shows editable pickup details. A missing field triggers a focused question.

Each new request, withdrawal or price change gives the assistant a reason to check the board again.

The shared board uses fictional aliases and a listed public pickup point.

Technical implementation

How a proposal is made

Read the intent. Match English input to the catalog. The offline parser works independently of an optional local model.

Check the board. Find common windows, price solo and shared baskets in integer sen, then select disjoint groups with the highest total net saving.

Track consent. The server keeps proposal versions and confirmations. A change in terms requires a fresh confirmation.

The English activity log comes from the matching and state transitions that actually ran.
Evidence and pilot design
